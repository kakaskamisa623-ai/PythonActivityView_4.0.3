PYTHON ACTIVITY VIEW 4.0.3
=========================

ИСПРАВЛЕНИЕ ДОЛГОГО СКАНИРОВАНИЯ ИСТОРИИ БРАУЗЕРОВ
---------------------------------------------------
- Для каждого профиля браузера установлен конечный лимит чтения: по умолчанию 35 секунд.
- Для всей отдельной проверки браузеров установлен общий предел: 180 секунд.
- SQLite Backup API копирует базу пакетами и регулярно сообщает объём обработанных страниц/МБ.
- Длительное ожидание блокировки или медленный SQL-запрос прерываются; источник получает
  статус timeout, а сканер переходит к следующему профилю.
- Если исчерпан общий лимит, оставшиеся профили явно получают статус not_scanned.
  Это не приравнивается к отсутствию истории.
- Долгие SQLite-запросы используют progress handler с проверкой отмены и дедлайна.
- В интерфейсе показаны номер профиля, браузер, профиль, размер БД и этап копирования.
- Счётчик прогресса переименован в «проверено источников»: это количество начатых
  операций чтения, а не общее число профилей, процент или гарантия завершения. В итоговой строке
  «не найдено» также учитываются отсутствующие стандартные варианты браузеров: если найден Chrome,
  остальные поддерживаемые варианты могут дать 14 записей not_found; это нормально и не означает
  зависание. Тайм-ауты/ошибки/пропуски отдельно видны в статусе источника.
- Базы браузеров по-прежнему открываются в режиме чтения; пароли и cookies не читаются.

НАЗНАЧЕНИЕ
----------
Универсальная локальная утилита для просмотра доступной истории Python, IDE и
терминалов, событий Windows, процессов, файлов Python, некоторых следов файловой
активности и текущих системных конфигураций. Программа не зависит от конкретной
игры, чита, лаунчера или приложения.

Проверка выполняется на том компьютере, где запущена программа, с согласия владельца.
Программа не подключается к удалённым компьютерам через AnyDesk самостоятельно.
При проверке через AnyDesk запустите утилиту на компьютере проверяемого пользователя.

ЗАПУСК
------
1. Установите Python 3.10+ для Windows с компонентом Tcl/Tk.
2. Распакуйте архив в отдельную папку.
3. Запустите Start_PythonActivityView.bat.
4. Для диагностики запуска используйте Start_Debug.bat.
5. Язык интерфейса переключается в верхней панели: русский, English, українська.
6. К защищённым системным журналам можно запросить доступ через стандартный UAC Windows.
   Автоматический запрос UAC — отдельная пользовательская настройка.




ЧТО НОВОГО В 4.0.0
------------------
- Добавлено полноценное локальное дело: название, заметки, пользовательский контекст,
  реестр выбранных файлов-доказательств, журнал действий и переносимый пакет .pavcase.
- Добавление доказательств работает по явному выбору оператора: выбранные файлы копируются
  в хранилище дела, исходники не изменяются. При копировании сверяются размер и SHA-256.
- Для каждого файла сохраняются исходный путь, размер, SHA-256, время добавления и заметка.
  Повторная проверка показывает missing/hash_mismatch/error/ok; доказательство можно
  исключить из пакета без удаления его локальной копии.
- Добавлена цепочка хешей журнала действий. Она обнаруживает изменение записи в сохранённой
  цепочке, но не является цифровой подписью и не защищает от переписывания всего дела
  лицом, имеющим доступ к файлу и умеющим пересчитать хеши.
- Добавлен переносимый формат .pavcase: ZIP-контейнер с case.json, выбранными копиями
  доказательств и manifest.json с SHA-256/размерами. Проверка манифеста выполняется до
  импорта; небезопасные пути и изменённые файлы отклоняются до распаковки.
- Добавлена глобальная форма Ctrl+F по уже загруженным результатам: Python/IDE/терминал,
  Windows events, браузер, загрузки, Python/Java, артефакты Windows, снимок процессов,
  локальные сессии, подписи и реестр доказательств. Поддерживаются Unicode/casefold,
  поиск с учётом регистра и регулярные выражения; исходные данные при поиске не меняются.
- Добавлено статическое сравнение двух EXE/DLL/JAR/файлов: SHA-256, размер, тип, архитектура,
  импорты, экспорты и секции. Сравнение метаданных не определяет вредоносность файлов.
- Добавлен PDF-экспорт отчёта (требует ReportLab и локальный Unicode-шрифт). Без этих
  дополнительных компонентов остаются штатные CSV/JSON/HTML/ZIP-экспорты.
- Добавлена диагностика среды и необязательных парсеров без сетевых запросов и изменения
  системных настроек. Проверка зависимостей не устанавливает и не обновляет пакеты.
- В PyInstaller spec включены новые модули дела, поиска, диагностики и PDF-экспорта.
  Windows EXE должен собираться на Windows; сам EXE в текущей Linux-среде не собран.
- Добавлены 11 тестов v4; совокупный тестовый набор содержит 92 теста.

ДОПОЛНИТЕЛЬНЫЕ ЗАВИСИМОСТИ ДЛЯ АНАЛИЗА КОДА DLL
---------------------------------------------
Встроенный PE-парсер работает без дополнительных пакетов. Для листинга машинных
инструкций установите Capstone до сборки EXE:
    python -m pip install capstone
Дополнительные метаданные PE можно расширить библиотекой pefile:
    python -m pip install pefile
После установки зависимостей пересоберите EXE через BUILD_EXE.bat.

ВАЖНО О ПРИВАТНОСТИ
-------------------
История браузеров по умолчанию не читается. Её включение может добавить личные URL,
заголовки страниц и пути загрузок в локальный отчёт. Пароли, cookies и содержимое
переписки не извлекаются. Перед экспортом или передачей отчёта просмотрите его вручную.
Посещение сайта или запись о загрузке не доказывают запуск файла либо использование чита.

- ZIP-пакет доказательств спрашивает отдельно, включать ли копии доступных исходных файлов

  выключен до события, задним числом Windows не создаёт отсутствующие записи.

  объединённое представление.
- Сохранены русский, английский и украинский интерфейсы, нижний терминал, отмена
  сканирования, кэш неизменившихся артефактов и сравнение снимков.
- В «Истории сканирований» можно импортировать JSON-отчёт или ZIP с report.json,
  чтобы вручную сравнить снимки, собранные на разных компьютерах. Импорт не подключается
  к удалённому ПК и не извлекает файлы из ZIP на диск.

ИСТОЧНИКИ WINDOWS И ОГРАНИЧЕНИЯ
-------------------------------
- Security 4688 может показать создание процесса, путь, PID/Parent PID и командную строку
  запуска только при соответствующей предварительной настройке аудита и записи
  командной строки. Событие 4689 содержит данные завершения процесса, если аудит включён.
- Security 4663 появляется только при настроенном аудите доступа к объектам и подходящей
  SACL для проверяемого объекта. Его отсутствие не означает, что файл не читался.
- Sysmon доступен только если он был установлен и настроен до проверяемой активности.
  Набор сохраняемых событий зависит от конфигурации Sysmon.
- PowerShell 4103/4104 может содержать сведения о командах/блоках сценариев только если
  соответствующее журналирование было включено заранее.
- Security 1102 и System 104 — события очистки журналов. 4719 — изменение политики аудита.
  Сами по себе эти события не доказывают, кто именно удалил следы или зачем.
- Для истории браузера отдельное событие удаления обычно недоступно в прочитанных базах.
  Вкладка признаков очистки показывает реальные события очистки журналов и отдельно пробелы
  покрытия; отсутствие посещений/загрузок не трактуется как доказательство очистки.
- Автоматический каталог Prefetch показывает инвентарь и стабильные поля заголовка. Для
  выборочного извлечения last/previous run timestamps нужен необязательный dissect.target.
  Сжатые MAM-файлы не обрабатываются встроенным декодером; результат parser следует сверять.
- Автоматическая проверка Amcache.hve/SRUDB.dat ограничивается доступностью и метаданными.
  Отдельно можно выбрать офлайн-копию Amcache.hve для выборочного извлечения известных
  веток через python-registry или SRUDB.dat для просмотра ESE через dissect.database.
  SRUM schema версионно-зависима; результаты не являются полным разбором всех таблиц.
- Prefetch/Amcache/SRUM/LNK/Jump Lists и EVTX могут содержать пользовательские пути,
  имена и временные метки. Используйте добровольно предоставленные копии и проверяйте
  их происхождение; источники не меняются приложением.
- USN Journal проверяется по доступности и метаданным через fsutil; журнал не выгружается
  целиком и удалённые записи NTFS не восстанавливаются.
- Задачи планировщика, службы и Run/RunOnce — текущий снимок конфигурации. Он не доказывает,
  что задача/служба запускалась в конкретный момент или что она связана с нарушением.
- Связь процессов по ProcessGuid предпочтительнее. Связь по PID ограничена временным
  окном, чтобы снизить риск ошибки при повторном использовании PID.
- Текущий снимок процессов не является историей и показывает только работающие сейчас
  процессы.
- AnyDesk trace — необязательный дополнительный источник; утилита не перехватывает ввод,
  не записывает клавиатуру удалённого сеанса и не читает содержимое других окон.

ГЛУБОКИЙ ПОИСК И ПРОИЗВОДИТЕЛЬНОСТЬ
----------------------------------
- Глубокий поиск идёт по доступным каталогам текущего профиля и ограниченному списку
  системных/прикладных корней. Это не полный секторный образ и не обход всех профилей.
- Кэш сокращает повторный разбор неизменённых файлов по пути, размеру и времени изменения.
  Поиск новых файлов всё равно перечисляет выбранные корни.
- Сканирование можно остановить на контрольной точке. Один уже выполняющийся системный
  вызов или чтение большого файла может завершиться до обработки отмены.
- Есть лимиты на число кандидатов и размер файлов/архивов, чтобы избежать зависаний.
- Неполные и недоступные источники отображаются отдельно от «не найдено».

ЗАПИСЬ СЕССИИ
-------------
Встроенная Python-консоль записывает только команды, введённые непосредственно в неё,
после явного включения записи пользователем. Она сохраняет время, ввод, stdout, stderr и
ошибки. Она не перехватывает ввод из PyCharm, CMD, PowerShell или других окон и не является
песочницей: код выполняется с правами текущего процесса. Не запускайте неизвестный код.

ПРАВА И ДОСТУП
--------------
- Повышение прав выполняется только штатным UAC Windows.
- Административные права могут открыть доступ к защищённым журналам/каталогам, но не
  включают аудит задним числом и не создают отсутствующие записи.
- При запуске с повышенными правами встроенная Python-консоль также унаследует повышенные
  права. Не запускайте в ней неизвестный код.

ЭКСПОРТ И ДАННЫЕ
----------------
- Доступны CSV, JSON, HTML и ZIP-пакет с report.json, events.csv и summary.html.
- Отчёты экспортируют точные собранные значения без маскирования. Если команда, журнал или
  параметр содержит пароль, токен, ключ или другую частную информацию, значение может
  попасть в экспорт. Просматривайте отчёт до передачи кому-либо.
- Обычный ZIP-отчёт сканирования не подписывается цифровой подписью и не имеет манифеста.

- SHA-256 отдельных исходных файлов может использоваться как метаданные файла при сборе;
  это не защищает отчёт и не доказывает подлинность события.
- Переносимое дело .pavcase содержит manifest.json с контрольными суммами файлов и журнал
  с цепочкой хешей. Это tamper-evident проверка, не криптографическая подпись личности.
- PDF-экспорт требует установленного ReportLab и доступного Unicode TrueType-шрифта.
- Глобальный Ctrl+F выполняет поиск только по уже загруженным в текущем сеансе данным;
  он не запускает повторное сканирование диска и не является индексатором всего компьютера.
- Сравнение файлов сопоставляет доступные статические метаданные и не доказывает связь
  или вредоносность сравниваемых файлов.
- Снимки сканирования хранятся локально в профиле пользователя; сохраняются последние
  40 снимков. Импортированные снимки также сохраняются локально и участвуют в сравнении.

Зависимости
-----------
Основной интерфейс использует Python 3.10+ и Tkinter. Системный анализ требует Windows,
wevtutil и PowerShell. Отдельные каналы могут отсутствовать, быть выключены или недоступны
без повышения прав. Программа не подключается к удалённым компьютерам самостоятельно.

Необязательные парсеры:
- EVTX: python-evtx; Amcache (офлайн): python-registry; LNK: LnkParse3.
- Prefetch: dissect.target; SRUM/ESE: dissect.database.
- Jump Lists: ANSSI dfir-jumplist-parser (проект помечен автором как beta; интерфейс может
  измениться). Установка и ограничения описаны в BUILD_EXE_RU.txt.
Необязательный parser должен быть установлен и при запуске .py, и в окружении сборки EXE,
чтобы PyInstaller включил его в one-file пакет.

ДОПОЛНИТЕЛЬНЫЕ ОГРАНИЧЕНИЯ 3.4.1
--------------------------------
- Audit Policy и статус Event Log показываются на момент сканирования; они не являются
  историей изменения политики. Для реконструкции прошлой настройки нужны ранее сохранённые
  события изменения политики, резервная копия или отдельный аудит.
- Временная метка без смещения сохраняется как есть; преобразование в UTC явно отмечается
  как предположение по часовому поясу системы. Смена часового пояса компьютера может влиять
  на интерпретацию старых локальных меток.
- Оценка «высокая» означает сильную запись конкретного источника, а не подтверждение умысла
  или нарушения. Сохранённая команда и процесс запуска — разные типы свидетельств.
- Сопоставление процессов не выполняет эвристическое объединение только по близкому времени.
  Если нужные PID/ProcessGuid/ID сессии отсутствуют в журналах, связь не строится.
- При включении копий в ZIP исходные файлы могут содержать частные данные. Лимит копий
  исходных файлов: 20 MiB на файл и 100 MiB суммарно; EVTX-файлы — до 50 MiB на канал.
- Копии и EVTX-экспорт создаются только по отдельному подтверждению при сохранении ZIP.
  Программа не очищает журналы и не меняет исходные файлы.

ИЗМЕНЕНИЯ 4.0.3 — СКАНИРОВАНИЕ АКТИВНЫХ БРАУЗЕРОВ
--------------------------------------------------
- Историю можно читать, не закрывая Chrome, Edge, Brave, Opera, Vivaldi или Firefox.
- Для основного пути программа напрямую открывает History/places.sqlite через SQLite URI
  mode=ro, включает PRAGMA query_only=ON и начинает read transaction.
- SQLite сама учитывает зафиксированные WAL-записи (committed WAL pages). Чтение видит
  согласованный снимок на момент начала транзакции; более новые записи, сделанные после
  начала сканирования, попадут в следующий запуск проверки.
- Исходная база не открывается на запись, браузер не завершается, не приостанавливается
  и не меняет свои настройки. Пароли и cookies не запрашиваются и не анализируются.
- При невозможности live read-only доступа используется ограниченный SQLite Backup API.
- Источник в отчёте содержит read_mode=live_readonly либо read_mode=sqlite_backup.
- Для долгого ожидания SQLite используется короткий busy timeout и цикл повторных попыток
  с проверкой отмены/дедлайна.
- Важное ограничение SQLite: чтение активной базы зависит от файловых ACL, наличия
  SQLite WAL/SHM и состояния базы. При эксклюзивной блокировке либо недоступных sidecar
  файлах профиль может получить ошибку/timeout; программа не обходит ACL и не останавливает браузер.

ИСПРАВЛЕНИЯ 4.0.2
-----------------
Если интерфейс показывал «источников: 14» и продолжал бесконечно вращать индикатор, число 14
означало число уже начатых операций чтения, а не 14 из 14 найденных профилей. В 4.0.2 подпись
счётчика уточнена. Для браузерных профилей показывается конкретный текущий этап. Один профиль
не может удерживать браузерную проверку бесконечно: по умолчанию действует лимит 35 секунд на
профиль и 180 секунд на всю отдельную проверку. Тайм-аут означает «источник не успел прочитаться»,
а не «история отсутствует». Остальные доступные профили продолжают обрабатываться.

Ограничение: эти сроки защищают браузерный анализ SQLite. Они не являются универсальным watchdog
для всех системных анализаторов полного сканирования. Реальные Windows-профили Chrome/Edge/Firefox,
особенно открытые и с большими WAL, нужно проверить отдельно на Windows 10/11.
